# Личный браузер регистрации AdGuard на Render

Экспериментальный сервис для одного владельца, одна активная сессия, 12 минут.
Telegram-бот создаёт Mail.tm-ящик и хранит данные на прежнем хостинге.
Render выполняет браузерные шаги на официальных страницах AdGuard. CAPTCHA решает человек
через изображение того же браузера; координаты нажатий/перетаскиваний передаются в его сессию.
Автоматического решения CAPTCHA, stealth-настроек, прокси и смены адресов нет.

## Состояние проверки

- Пройдены 19 тестов сервиса: авторизация, временные ссылки, согласие, изоляция,
  HTTP API, обработка ошибок без утечки текста и строгая проверка результата входа.
- Пройдены 64 теста Telegram-бота, включая передачу OTP, возобновление и проверку ответа Render.
- Синтаксис Python и JavaScript проверен.
- Docker-образ не собран локально. Реальный Chromium на Render, работа CAPTCHA,
  селекторы актуальной формы и расход памяти в 512 МБ пока НЕ подтверждены.
- Смена формы AdGuard или отказ провайдера CAPTCHA может потребовать доработки.
  Неудача или тайм-аут не выдаются за готовый аккаунт. Платная подписка VPN не создаётся.

## 1. GitHub

Распакуй архив проекта. Загрузи его внутренние файлы в корень репозитория
https://github.com/korewq11/adguard-browser через Add file → Upload files → Commit changes.
Dockerfile должен быть прямо в корне, не во вложенной папке.
Сам ZIP GitHub не распаковывает: загружать вместо файлов архив не нужно.
Не загружай сюда Telegram-бота, токены, state.bin, .storage.key или .env.

## 2. Render

На экране Public Git Repository вставь:

    https://github.com/korewq11/adguard-browser

Нажми Connect, затем установи:

- Name: adguard-browser (или доступное имя).
- Branch: основная ветка репозитория.
- Runtime/Language: Docker.
- Root Directory: пусто.
- Dockerfile Path: ./Dockerfile, если поле отображается.
- Instance Type: Free, 512 MB. Не выбирай платный тариф.
- Health Check Path: /health в дополнительных настройках.
- Environment Variable BROWSER_SERVICE_KEY: случайная строка длиной не менее 32 символов.

Например, сгенерировать новый ключ на своём ПК или в приватной Shell можно командой:

    python -c "import secrets; print(secrets.token_urlsafe(32))"

Это отдельный ключ связи двух твоих серверов, НЕ токен Telegram-бота.
Его значение понадобится на обоих хостингах. Не публикуй его в GitHub.
Запусти Deploy Web Service. Chromium устанавливается при сборке Docker, а не при каждом пробуждении.
Команды Build/Start вручную для Docker вводить не нужно.

Успешный /health означает только, что HTTP-сервис работает. Браузер запускается лениво,
при первой регистрации; его запуск и CAPTCHA этим запросом не проверяются.
Render автоматически даёт RENDER_EXTERNAL_URL; сервис использует его для временных ссылок.
Если переменная не установлена либо используется свой домен, задай PUBLIC_BASE_URL
равным HTTPS-адресу сервиса без пути и параметров.

Альтернатива ручной настройке — Blueprint из render.yaml; при этом ключ генерирует Render.

## 3. Подключить существующего Telegram-бота

Когда Render показывает Live, сохрани его адрес вида:

    https://adguard-browser-xxxx.onrender.com

На Bot-Hosting.net останови бот, замени только main.py на отдельно выданное обновление.
Сохрани state.bin, .storage.key, требования cryptography и прежний TELEGRAM_BOT_TOKEN.
В «Окружение» добавь:

    BROWSER_SERVICE_URL=https://adguard-browser-xxxx.onrender.com
    BROWSER_SERVICE_KEY=тот_же_самый_ключ_что_на_Render

Перезапусти бота. Telegram-токен и ключ шифрования состояния на Render передавать НЕ нужно.
Если обе BROWSER_SERVICE_* переменные отсутствуют, бот сохраняет старый прямой HTTP-режим.
Если заполнена только одна переменная, бот сообщает об ошибке, а не пытается создать новый ящик.

В Telegram нажми «➕ Создать аккаунт», затем подтверди условия.
Старый незавершённый аккаунт продолжится на том же адресе: не удаляй состояние ради повторной попытки.

## 4. Ручная CAPTCHA

1. Бот обращается к Render, будит его и запускает сессию.
2. Браузер заполняет стандартные поля и согласие с условиями; рекламные флажки не выбирает.
3. При CAPTCHA или неизвестном шаге бот присылает временную ссылку.
4. Открой её в браузере, нажимай на элементы CAPTCHA в изображении.
   Поддерживаются нажатия, перетаскивание, прокрутка, Tab, Enter, Escape, Backspace и ввод текста.
5. Нажми «Продолжить» НАД изображением после решения CAPTCHA.
6. Код из почты бот передаст автоматически. Для подтверждения ссылки вместо числового кода
   отдельная браузерная обработка не реализована; неизвестный шаг может потребовать ручного действия.
7. Для проверки пароля сервис закрывает первый контекст, создаёт новый без cookies и входит заново.
   CAPTCHA может потребоваться ещё раз. Если форма выбрала вход по коду, переключись на вход с паролем
   в изображении и нажми «Продолжить»; автоматически сервис также пытается найти этот переключатель.
8. Готовность выставляется только при confirmed=true и успешном ответе входа с ожидаемыми
   email и паролем именно в новом контексте. Сам факт решения CAPTCHA не означает готовность.

Ссылка даёт полный ручной контроль только этой сессии. Не пересылай её.
Токен находится во фрагменте URL, затем сохраняется в sessionStorage, и не попадает в HTTP-путь.
API бота использует отдельный серверный ключ; браузерный токен не позволяет отправлять OTP через API.
Все ответы запрещают кеширование. Обычный access log отключён.

После закрытия страницы бот продолжает активную регистрацию максимум до конца её 12-минутного окна.
При ручном «Остановить» браузер закрывается. Повторная попытка из бота использует тот же почтовый ящик.
Запросы выполняются только во время реальной работы, искусственного поддержания Render в бодрствовании нет.
Когда нет регистрации или пользователя, входящих запросов нет, и Render может заснуть по правилам Free.

## Данные и ограничения

- Учётные данные хранятся в памяти Render только на время сессии; пароль очищается при закрытии.
- Постоянное зашифрованное состояние остаётся на Bot-Hosting.net, как раньше.
- Сон/перезапуск/исчерпание памяти Render уничтожает браузер, cookies и его состояние.
  Продолжить именно потерянную CAPTCHA-сессию невозможно: понадобится новая с тем же адресом.
- Только один браузер и одна страница. Не запускай несколько регистраций параллельно.
- Изображения/JavaScript CAPTCHA не блокируются; реклама в письмах не пересылается.
- Аудиопоток удалённого браузера не реализован; подходит визуальное ручное взаимодействие.
- Любой статус manual требует посмотреть сообщение в форме, а не обязательно решить CAPTCHA.
- Длинная регистрация синхронна: Telegram-команды бот обработает после её завершения;
  остановить активную попытку можно кнопкой на странице браузера.
- 512 МБ не гарантированы достаточными: при OOM контейнер может перезапуститься.
- Ошибки/429 не обходятся и не запускают бесконечных повторных POST регистрации.
- Никакой публичной навигации на произвольные сайты в API нет; верхние страницы ограничены AdGuard.

## Если Chromium не запускается

Сначала пришли последние строки Render Logs БЕЗ секретных переменных и временной ссылки.
По умолчанию включена песочница Chromium, процесс работает не от root.
Если лог ЯВНО сообщает о запрете Linux namespaces/No usable sandbox, а не нехватке RAM или библиотек,
можно отдельно решить, допустим ли для твоего приватного сервиса режим BROWSER_NO_SANDBOX=1.
Он отключает внутреннюю песочницу Chromium, снижает изоляцию и по умолчанию НЕ включён.
Не используй этот параметр как универсальный фикс и не публикуй сервис без серверного ключа.
